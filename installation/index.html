Installation

Get Spicy running on the computer at your counter. This should take about 20 minutes.

What you need

RequirementNotes
A computerThis becomes your till. It stays on during trading.
Three thermal printersOne for receipts, one for the kitchen, one for the bar. Kitchen and bar printers are on the network.
PostgreSQLHolds all your data. Comes with Docker, which is the easiest way to run it.
Python 3.14+Runs Spicy.
Node.js and npmBuilds the buttons and styling.
DockerRuns PostgreSQL and Redis for you. Optional but recommended.

Use a wired connection for the till. The cashier's computer should be on Ethernet where possible. If the network drops mid-shift, the system stops accepting orders, and you do not want that on Wi-Fi.

Install

Step 1: Get the code

git clone https://github.com/sanusi-dev/spicy.git
cd spicy

Step 2: Start the database

This copies a sample settings file, starts PostgreSQL and Redis, creates your database tables, and installs the front end files.

make init

It may take a few minutes on the first run while everything downloads.

Step 3: Start Spicy

make dev

Leave this running. Spicy is available at localhost:8000.

Step 4: Create your administrator account

While Spicy is running, open a second terminal in the same folder and run:

make manage ARGS='createsuperuser'

Pick a username and password. This is the administrator account. Use it to sign in and create accounts for your staff.

Step 5: Load the standard accounts

Spicy needs a set of accounts before it can record a sale — things like Food Sales, Cash Account, and Cost of Goods Sold. This command sets those up, along with sample items and prices so you can try things out.

make manage ARGS='seed_pos_setup'

Delete the sample items before you trade. They are placeholders. Clear them out and add your own in Setup.

Check it worked

Sign in at localhost:8000. An administrator lands on the back office dashboard.

To confirm there are no problems, run:

make manage ARGS='check'

A healthy install reports System check identified no issues.

Before you take real orders

Three things to sort out first.

Turn off debug mode

Open the .env file and set:

DEBUG=False

Debug mode is for development. Leaving it on lets anyone signed in as an administrator change your sales and stock figures directly, bypassing the safety checks. Do not trade with it on.

Set your own secret key

Run this to generate one:

python -c "import secrets; print(secrets.token_urlsafe(64))"

Paste the result into the SECRET_KEY line in .env. This key protects your staff logins. If you skip it, anyone who reads the public source can sign in as your staff.

Set your time zone

Spicy uses your computer's clock to decide which trading day a sale belongs to. If you close at 3am, that sale still counts for the previous day. Make sure the computer's date, time, and time zone are correct — check the automatic time setting in your operating system.

Printing

Spicy prints through a small helper on the same computer. It talks to your receipt printer directly, and to the kitchen and bar printers over the network.

Once it is running, add each printer in Setup under Production Units: its IP address, whether it prints receipts or tickets, its paper width, and whether it cuts the paper off after printing.

A printer problem will not stop you selling. If a printer is unreachable, the sale still goes through and you get a warning. But the kitchen will not receive the food, so nothing gets cooked. Fix the printer before you trade.

Running it every day

When you switch the till on in the morning:

  1. Start Docker and the database: make start-bg
  2. Start Spicy: make dev
  3. Open the POS and open your shift

Leaving make dev running in a terminal window works, but it stops if you close that window or log out of the computer. For a permanent setup, ask whoever set it up to run Spicy as a service that starts automatically.

Backing up

From day one, take a backup every night:

make backup

This saves your sales data and your item photos to the backups folder. Set it to run automatically after you close, and copy the files to another drive weekly. A backup sitting on the same computer does not help if that computer is stolen.

Run it once by hand now, before you have any real data, so you know it works and you can find the files.
